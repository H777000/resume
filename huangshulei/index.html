  • 沁言自传

    让作者从访谈记录进入提纲和章节编辑，接着写自己的故事。

    方案详情
    流程设计
    访谈、提纲、章节是三个连续的编辑阶段。作者打开一本书时，需要看清正在编辑哪一章，以及该章已有的内容。
    前端实现
    参与 React / TypeScript 前端开发与接口联调，将服务端返回的创作内容对应到当前编辑阶段和章节。
    验收要点
    沿访谈记录打开提纲，再切换章节，逐项核对章节标题与正文是否对应。

  • 金榜数学

    让学生在练习页围绕当前题目提问，并继续追问解题步骤。

    方案详情
    交互设计
    在练习页衔接题干与问答，让学生提问时沿用正在做的题目。
    前端实现
    参与 React / TypeScript 页面开发与接口联调，处理当前选题、题干展示与提问上下文的对应关系。
    验收要点
    在同一题上连续追问，再切到另一题提问，核对两次提交各自关联的题目。

  • loop-engineering

    给跨多轮执行的 Agent 保留任务状态、验证记录和停止条件。

    方案详情
    执行设计
    先从项目中选一个有明确验证方法的任务。执行后留下结果和证据，再决定继续、停止或交给人判断。
    实现方式
    Python 脚本初始化工作目录，整理项目特征与候选任务。结果记录写入本地文件，供下一轮读取。
    验证方式
    从一次手动运行检查任务选择、验证命令与结果记录，确认下一轮能还原上一次停在哪里。

  • daily-work-report

    从 Git 记录整理日报和周报，让每项进展都能追溯到证据。

    方案详情
    规则设计
    分别记录本地改动、分支推送、合并、部署与验证。只有对应证据齐备，报告才使用相应的进度表述。
    实现方式
    Python 采集指定仓库和日期范围内的提交与分支活动，生成 JSON 证据文件，再按个人模板输出中文报告。
    验证方式
    从报告条目回查证据文件。例如只有分支提交记录时，进度应停在该分支的实际状态。

  • html-to-editable-pptx

    把 HTML 幻灯片导出为 PowerPoint，方便接手的人继续改字、调版。

    方案详情
    转换设计
    读取 Chromium 渲染后的页面布局，把文字转成原生文本框，可映射的图形转成形状，复杂 CSS 装饰单独转成图片。
    实现方式
    通过 Node.js 命令行调用浏览器完成转换，逐页报告可编辑文本框、映射图形与局部图片的数量。
    验证示例
    仓库示例导出 14 个原生文本框。修改其中一段文字后重新渲染，对照原始 HTML 检查改字结果和版式。
